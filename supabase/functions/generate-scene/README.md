# generate-scene

Драматург (docs/ENGINE.md §2–10, docs/ROADMAP.md, этап 2). Берёт одну
зацепку (`catch_id`), собирает вокруг неё семя из личного словаря символов,
карты персонажей, подтверждённых паттернов и недостающих осей профиля,
зовёт модель по контракту и не пускает результат в базу, пока он не
пройдёт `lib/validate_story.ts`.

## Структура

```
index.ts               обработчик Deno.serve: сбор досье → генерация → валидация с повтором → запись
deno.json               import map для esm.sh
lib/
  contract.ts           типы кандидата истории (зеркало ENGINE §2, §4, §6)
  validate_story.ts      страж контракта — главный модуль, см. ниже
  banned_phrases.ts      запреты ENGINE §10 (предсказания, утечка джйотиш, насилие как решение...)
  text.ts                подсчёт слов
  prompt.ts              сборка system+user промпта из «досье» семени
  extract_json.ts        достаёт JSON из ответа модели, даже если он обрамлён пояснением
  anthropic.ts           вызов Anthropic Messages API — единственный Deno-специфичный модуль в lib/
  dossier_format.ts      сырые строки top_entities/choice_profile_axes → формулировки для промпта
  mute_check.ts          право вето: активен ли кризисный протокол (safety_events)
test/                   тесты для всех lib/*.ts, кроме anthropic.ts, на node:test
fixtures.ts             валидная история-образец для мутации в тестах validate_story
```

## Почему валидатор — центр этого модуля

`lib/validate_story.ts` дублирует те же правила, что зашиты триггерами в
`supabase/migrations/0001_init.sql` (`scenes_total_in_range`,
`scenes_choices_count`, `scenes_anchor_on_last`, `choices_shape`) — так, что
плохой кандидат отклоняется ДО обращения к базе, с конкретным списком
нарушений, а не падает загадочной ошибкой constraint. Плюс правила,
которые в схему не переносятся: объём сцены в словах, запрещённые
формулировки (`banned_phrases.ts`), момент введения архетипа «Самость».

Генерация не проходит как есть, если провалилась: `index.ts` перезапрашивает
модель до `MAX_GENERATION_ATTEMPTS` раз, передавая ей точный список
нарушений. Если после всех попыток кандидат так и не прошёл — функция
отвечает 502 со списком причин, ничего не записывая в базу.

## Право вето safety-guardian

Перед любой генерацией функция проверяет `safety_events.mutes_interpretation_until`
для пользователя (`lib/mute_check.ts`). Если кризисный протокол сработал
недавно — следующие 7 дней истории не генерируются вообще, функция отвечает
403 ещё до обращения к модели. Это не декларация в документах, а код,
который реально исполняется на каждый вызов.

## Тесты и типы

```bash
node --experimental-strip-types --test supabase/functions/generate-scene/test/*.test.ts

cd supabase/functions/generate-scene && ../../../app/node_modules/.bin/tsc -p tsconfig.json
```

62 теста, включая мутационные проверки validate_story (каждое нарушение
контракта — отдельный тест, а не один общий «плохая история отклоняется»).
`anthropic.ts` — единственный файл без юнит-тестов (вызывает реальный
внешний API); typecheck покрывает и его, и `index.ts` — см. пояснение в
README `catch-ingest` про `../_shared/deno_types.d.ts`.

## Известные границы этой итерации (не баги, а объявленный объём)

1. **`chartThemes` уходит пустым списком.** Джйотиш-движок (ENGINE §3) ещё
   не построен — без него нечем заполнить драматургические темы карты.
   Пока это честная пустота, а не выдуманные темы; `seed.blind_spot_to_seed`
   и активные паттерны частично компенсируют отсутствие карты (CONCEPT §11:
   без даты рождения предустановки и так выводятся из дневника).
2. **`showMechanics` всегда `false`.** Пользовательской настройки тумблера
   «показать механику» в схеме ещё нет — задел на будущее поле в `users`.
3. **Только `mode='first_pass'`.** Второй проход и «та же зацепка через
   полгода» (`second_pass`/`replay_after_months`, ENGINE §8.6–8.7) — это
   повторный `run` на СУЩЕСТВУЮЩЕМ `seed_id`, отдельная точка входа,
   которую эта функция не реализует.
4. **`field_task.unlocks_scene`** всегда трактуется как «следующая по
   индексу сцена» — контракт кандидата не даёт модели указать иной адрес,
   а следующая сцена — единственный осмысленный вариант по умолчанию.
5. **Гонка при одновременной генерации двух историй по одной зацепке**
   не блокируется явно: ничего в спецификации не запрещает несколько семян
   от одной записи, поэтому функция не вводит искусственное ограничение.
